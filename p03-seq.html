序列建模与编码器-解码器

1什么叫“序列建模”

序列就是一串有顺序的东西：一句话、一段语音、一支股票的每日收盘价。 序列建模指的是：给定前面的一部分，预测接下来的部分。

注意“有顺序”这三个字。如果把一句话打乱成词袋 {动物, 这只, 累, 很}，意思就没了。 所以任何序列模型都必须处理顺序——要么靠结构天然带顺序（RNN 一步步读）， 要么显式注入位置信息（Transformer 的做法，见第 13 页）。

语言模型language model§1；§3 第一段

是什么：一个计算“给定前文，下一个词是各个词的概率”的模型： P(wt | w1, …, wt−1)。

为什么需要：翻译、摘要、问答本质上都是“生成一串词”。只要有了下一个词的概率， 就能一个词一个词地把整句写出来。

训练信号从哪来：不需要人工标注。拿真实文本，把第 t 个词当答案、前 t−1 个词当输入， 就叫自监督。这也是为什么这类模型能吃下海量数据。

易错：语言模型不是“理解后翻译”，它只是在做概率预测。所谓“理解”，是从预测准确率里涌现出来的副产品。

2RNN：一步一步读

RNNrecurrent neural network§1 第一段

是什么：按时间步依次处理序列的网络。它维护一个隐藏状态 h， 每读一个词就更新一次：ht = f(ht−1, xt)。

直观理解：像一个人一边读一边在脑子里做笔记。读完“这只动物没有过马路”， 笔记里存着“有一只会过马路的动物”；读到“它”时，笔记帮着回忆指的是谁。

致命约束：ht 依赖 ht−1，所以第 5 步必须等第 4 步。 这在数学上是串行的，无法用并行硬件加速。

易错：RNN 并不是“读得慢”，而是不能并行。单步计算很快，但它必须做 n 次， 而 GPU 的强项是一次做一万件事。
1RNN 处理一句话的完整流程n 步串行
输入
词向量序列 x₁, x₂, …, xn；初始隐藏状态 h₀（通常全零）
条件
必须按 t = 1, 2, …, n 的顺序执行，不能跳步
步骤 1
算 h₁ = f(W·x₁ + U·h₀ + b)
步骤 2
把 h₁ 与 x₂ 一起送进去，算 h₂
步骤 3
重复到 hn。每个 ht 都可以拿去做预测或传给解码器
结果
n 个隐藏状态；最后一个 hn 通常被当作“整句摘要”
易错
① 以为可以并行算各步（不行，依赖前一步）； ② 以为 hn 保留了全部信息（它是个固定长度向量，长句必然丢东西）。

毛病一：不能并行

假设一句 50 个词。RNN 必须做 50 次串行计算，GPU 的 5000 个核心大部分时间在闲置。 训练时更糟：为了让梯度传回去，还得再反向走 50 步。

Transformer 的解法是把这条链彻底剪断：所有词同时进入网络，任意两个词之间只隔一次注意力计算。

毛病二：长距离依赖会衰减

信息从第 1 个词传到第 50 个词，要经过 49 次“重新编码”。每经过一次都是一个线性变换加激活， 信息会被不断改写、稀释。结果是：模型很难学会“第 50 个词指代第 2 个词”这种关系。

论文用路径长度（path length）来量化这件事：RNN 的路径长度是 O(n)， 自注意力是 O(1)。表 1 就是这个对比。

长距离依赖long-range dependency§1；§4

是什么：序列中相隔很远的两个元素之间的关系。例如“它”要指代 20 个词之前的“动物”。

为什么难：信号要经过很长的一条计算路径才能相遇，路径越长，越容易在传递中丢失。

易错：LSTM/GRU 的门控机制只是缓解了衰减，没有消除串行性，路径长度依然是 O(n)。所以它们不是 Transformer 的竞争对手，而是同一个问题的不同妥协。

3编码器-解码器：翻译的标准框架

翻译的难点在于输入输出长度不同、词序也不同。2014 年前后定下来的标准解法是把任务拆成两半：

编码器encoder§3 第一段；§3.1

是什么：把输入序列 (x₁…xn) 读成一个表示 z = (z₁…zn)。 它的任务只有一个：理解，不生成任何东西。

在 Transformer 里：6 层堆叠，每层 = 自注意力 + 前馈网络。输出仍然是 n 个向量（每个位置一个）。

易错：编码器输出不是“一个向量”，而是n 个向量。早期的 seq2seq 才把它压成一个；Transformer 保留了每个位置的表示，这正是它能做交叉注意力的前提。
解码器decoder§3 第一段；§3.1

是什么：根据编码器的表示 z 和已经生成的词，逐个预测下一个词，最终输出序列 (y₁…ym)。

关键性质：它是自回归的——每生成一个词，就把它接到输入末尾，再预测下一个。

易错：解码器一次只往前推一个词（推理时）。训练时可以整句并行喂入，但那是靠掩码伪装的并行，见第 10 页。
seq2seq 框架sequence-to-sequence§3 第一段

是什么：“编码器 + 解码器”这套组合的统称，用于输入输出都是变长序列的任务（翻译、摘要、对话）。

历史位置：Sutskever 等人 2014 年提出，之后两年所有翻译系统都长这样。Transformer 没有推翻这个框架， 只是把里面的 RNN 换成了注意力——这一点非常重要，论文 §3 的第一句就在强调它沿用了这个结构。

易错：Transformer ≠ 编码器-解码器。后来 BERT 只用编码器，GPT 只用解码器，都叫 Transformer。论文原版是完整的编码器-解码器。

那个“瓶颈”问题，以及注意力的第一次登场

最早的 seq2seq 把编码器最后一步的隐藏状态 hn 当作整句摘要，喂给解码器。 问题很明显：一句 50 个词的信息，被硬塞进一个固定长度的向量里，必然丢细节。

2015 年 Bahdanau 等人提出：让解码器每一步都回头看一眼编码器的所有隐藏状态， 并自动决定该看哪几个。这就是注意力机制的由来——它最初只是一个补丁，用来解决长句翻译的瓶颈。

Transformer 的洞察是：既然注意力这么好用，那还要 RNN 干什么？把循环整个删掉，只留注意力。 论文标题 “Attention Is All You Need” 说的就是这件事。

因果链条记住这一条就够了：RNN 不能并行且长距离衰减 → 用它做编码器解码器有瓶颈 → 加注意力当补丁 → 补丁效果太好 → 干脆把 RNN 删了，全用注意力 → Transformer。

本页要点

  1. 语言模型 = 预测下一个词；训练信号来自文本自身，不需要人工标注。
  2. RNN 用隐藏状态逐步传递信息，因此无法并行，且路径长度为 O(n)，长距离依赖会衰减。
  3. LSTM/GRU 只缓解衰减，没有解决串行性。
  4. 编码器-解码器把“理解”和“生成”分开；早期瓶颈是把整句压成一个向量。
  5. 注意力最初是为解决这个瓶颈而加的补丁；Transformer 把它变成唯一的主角。

5自测

Q1RNN 无法并行的根本原因是？
这是“数据依赖”而不是“算力”问题。只要 h_t 需要 h_{t-1}，就必须等，硬件再强也没用。
Q2论文说自注意力的“最大路径长度是 O(1)”，这句话的意思是？
路径长度衡量“信号要走几步才能从一个位置到另一个位置”。自注意力一步到位，RNN 要走 n 步。路径越短，越容易学长距离关系。
Q3注意力机制最早是为了解决什么问题被提出的？
Bahdanau 等人 2015 年提出让解码器回看编码器的所有状态。Transformer 的贡献不是发明注意力，而是证明可以只用注意力。
