12正文·§3.4

嵌入与 Softmax：模型的两端

一头把词元编号变成向量，一头把向量变回词概率。这一节还藏着一个非常实用的工程技巧：三处共享同一张权重表。

前置：第 01、04 页 对应：§3.4 约 16 分钟
为什么学这一页
论文位置§3.4
不学卡在哪一个词怎么变成 512 个数字；最后又怎么变回一个词。
它解决什么这是模型的两端——输入怎么进来、输出怎么出去，中间所有运算都建立在它之上。

1原文三句话

“we use learned embeddings to convert the input tokens and output tokens to vectors of dimension dmodel. We also use the usual learned linear transformation and softmax function to convert the decoder output to predicted next-token probabilities. In our model, we share the same weight matrix between the two embedding layers and the pre-softmax linear transformation … In the embedding layers, we multiply those weights by √dmodel.”

三句话对应三件事：查表、共享、缩放。第三件最容易被忽略，也最容易被问“为什么”。

2嵌入层：一张可学习的查找表

「查表」这个说法，看一遍就清楚了：

嵌入embedding§3.4

是什么：一个形状为「词表大小 × dmodel」的矩阵。第 k 行就是第 k 个词元的向量表示。

怎么用：输入一个词元 ID，取出对应那一行。没有乘法，就是查表（lookup）。

为什么是“可学习的”：这张表初始随机，训练时随梯度更新。语义相近的词会被推到相近的位置。

易错：嵌入层参数量很大（37000×512≈1900 万），几乎占了 base 模型 6500 万参数的三成。 但它是稀疏更新的——一个批次只碰到几千行，其余行的梯度为 0。
1查表操作3 步
输入
词元 ID 序列，例如 [1834, 92, 7]
条件
ID 必须在 [0, 词表大小) 范围内，越界会直接报错或读到脏数据
步骤 1
对每个 ID，取嵌入矩阵的第 ID 行，得到一个 512 维向量
步骤 2
把 n 个向量堆成 n×512 的矩阵
步骤 3
整体乘以 √dmodel（base 模型约 ×22.6）
结果
n×512 的输入矩阵，随后与位置编码逐元素相加
易错
① 忘记乘 √dmodel，导致词向量被位置编码淹没； ② 把嵌入层当成线性层去乘整个 one-hot 矩阵（数学等价但慢几百倍）。

3为什么乘 √dmodel

论文只说了“乘”，没解释原因。通行的解释是这样：

  • 嵌入矩阵通常用很小的值初始化（比如标准差 0.02），训练初期词向量的每个分量都很小。
  • 位置编码的值域固定在 [−1, 1]，量级约 1。
  • 两者直接相加，位置编码会压倒词向量——模型看到的主要是“这是第几个词”，而不是“这是什么词”。

乘 √dmodel ≈ 22.6，把词向量的量级抬到与位置编码相当，相加后两者都有存在感。 另一个流传的解释与“保持方差”有关：若每个分量方差为 1/dmodel，乘 √dmodel 后方差回到 1。

诚实标注：原文没有给出推导，以上是基于后续实践与常见实现的解释。 读论文时看到“只说怎么做、不说为什么”的地方，要意识到这是作者的省略，不是你的理解问题。

4权重共享：一处定义，三处使用

论文把同一个矩阵用在了三个地方：

  1. 输入嵌入（源语言词元 → 向量）
  2. 输出嵌入（目标语言词元 → 向量）
  3. softmax 之前的线性层（隐状态 → 词表分数），用的是它的转置
位置形状作用
输入嵌入37000 × 512查表得到词向量
输出嵌入37000 × 512同上，用于目标语言
pre-softmax 线性层512 × 37000用同一矩阵的转置，把 512 维映射到词表

为什么可以共享

因为它们在语义上是同一件事的两个方向：嵌入是“词 → 向量”，输出层是“向量 → 词”。 如果“动物”的向量是 v，那么一个向量越接近 v，它就越应该是“动物”——这正好是同一个几何关系。

共享的好处很直接：参数量从 3×1900 万降到 1900 万，省下约 3800 万参数； 同时低频词的嵌入和输出得到联合训练，学得更充分。

注意措辞：论文说的是 “share the same weight matrix between the two embedding layers and the pre-softmax linear transformation”。三个地方共享同一个矩阵，不是两两共享。

5输出端：从 512 维到 37000 个概率

2输出层2 步
输入
解码器最后一个子层输出的 512 维向量 h
条件
线性层权重与嵌入矩阵共享（转置后使用）
步骤 1
logits = h · ET，得到 37000 个分数
步骤 2
softmax，得到总和为 1 的概率分布
结果
每个候选词一个概率；训练时与真实词算交叉熵，推理时用于采样或贪心选择
易错
以为输出层只算一个词（实际要对整个词表打分，这是推理的主要开销之一）。

这也解释了一个现象：词表越大，输出层越慢。37000 个分数的计算量是 512×37000 次乘加， 每生成一个词都要做一遍。后来很多工程优化（如采样、分层 softmax）都在打这个点的主意。

本页要点

  1. 嵌入层是一张「词表 × 512」的查找表，训练时更新，参数量占模型约三成。
  2. 查表后要乘 √dmodel，让词向量与位置编码量级相当（原文未解释，属通行解读）。
  3. 输入嵌入、输出嵌入、softmax 前的线性层共享同一个权重矩阵。
  4. 共享既省参数（约 3800 万），又让低频词学得更充分。
  5. 输出层每步对整个词表打分，是自回归推理的主要成本之一。

6自测

Q1论文中共享权重的是哪几处？
层与层之间不共享（§3.3 明确说了 layer to layer 参数不同）。共享只发生在嵌入与输出层之间。
Q2嵌入向量为什么要乘 √dmodel？
缩放不改变参数量。原文未给推导，主流解释是量级匹配（也与保持方差到 1 的说法相关）。
Q3输出层的权重矩阵形状是？
隐状态是 512 维，输出是词表大小，所以是 512×37000。它等于嵌入矩阵 E（37000×512）的转置。
