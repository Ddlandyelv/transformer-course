向量、矩阵与点积

Transformer 里 95% 的计算是矩阵乘法。如果 QKT 对你来说是一串看不懂的符号， 这一页会把它拆成“一堆数相乘再相加”这么简单的事。

前置：无 用于：第 08 页 注意力 约 20 分钟
为什么学这一页
论文位置§3.2.1 式(1) 的 QKᵀ；§3.3 式(2) 的 xW
不学卡在哪看到 Q·Kᵀ 不知道在算什么；不知道 512×2048 的矩阵为什么这样写。
它解决什么注意力与 FFN 的全部运算都是矩阵乘法，不熟就没法验算论文里的任何一个数字。

1为什么读论文前必须先懂这些

论文里最核心的公式只有一行：

Attention(Q, K, V) = softmax(QKT / √dk)V 论文式 (1)

这一行里出现了三个数学动作：矩阵乘法（QKT）、转置（上标 T）、 逐元素缩放（除以 √dk）。如果不知道矩阵乘法的形状规则，你就无法判断 QKT 会得到一个什么样的东西——而它的形状（n×n）恰恰是理解“每个词和每个词打分”的关键。

所以本页的目标很具体：让你能亲手算出 QKT 里的任意一个数，并且知道它的行列分别代表什么。

2向量：一个词就是一组数

向量vector§3.4

是什么：一串有序的数，写在方括号里，例如 [0.2, −1.3, 0.7, 0.0]。 每个位置叫一个分量（component），分量的个数叫维度。

为什么需要：神经网络只认数字。要把“动物”这个词喂给模型，必须先把它变成一组数。 这组数就是这个词的“坐标”——意思相近的词，坐标也相近。

论文里的样子：每个词元都被表示成一个 512 维向量（base 模型）。一句话有 10 个词， 就是 10 个 512 维向量，堆在一起是一个 10×512 的矩阵。

易错：向量的“维度”和矩阵的“维度”不是一回事。向量的维度 = 分量个数（如 512）； 矩阵说维度时通常给两个数（如 10×512 = 行数×列数）。读论文时看到 dmodel=512，指的是列数。

一个具体的例子

假设我们只用 4 维来表示词（论文是 512 维，这里缩小到 4 维方便手算）：

猫 = [0.9, −0.2, 0.4, 0.1]   ·   狗 = [0.8, −0.1, 0.5, 0.0]   ·   汽车 = [−0.7, 0.6, 0.1, 0.8]

猫和狗的向量很接近（每一格都差不多），汽车则差别很大。这就是“词义被编码进了数字”的直观含义。 注意：每一格具体代表什么，人类是读不出来的——它是模型自己学出来的抽象特征。

3点积：注意力打分的唯一工具

点积dot product · 内积§3.2.1

是什么：两个长度相同的向量，对应位置相乘，再把所有乘积加起来，得到一个数（标量）。

公式：a · b = a₁b₁ + a₂b₂ + … + aₙbₙ

为什么需要：它是衡量“两个向量有多相似”最便宜的办法。结果越大，方向越一致； 等于 0 说明两者垂直（无关）；为负数说明方向相反。

易错：点积要求两个向量维度完全相同。3 维向量不能和 4 维向量做点积。 另外别把点积和“逐元素相乘”搞混——后者得到的是向量，不是数。
1手算一次点积4 步
输入
向量 a = [2, 0, 1]，向量 b = [1, 3, 2]
条件
两者维度必须相同（这里都是 3 维）。不相同就无法计算，这是硬性前提。
步骤 1
把两个向量按位置对齐：(2,1) (0,3) (1,2)
步骤 2
逐对相乘：2×1=2，0×3=0，1×2=2
步骤 3
把所有乘积相加：2 + 0 + 2 = 4
结果
点积 = 4。这是一个数，不是向量。
易错
漏掉某一维（尤其是 0 的那一维）；把“相加”写成“相乘”；负数符号丢掉。 0×3 的贡献是 0，但不能不写——它参与了求和的位置对齐。

为什么“点积大”等于“相关”

几何上有恒等式：a · b = |a| × |b| × cos θ，θ 是两个向量的夹角。 当两个向量方向一致（θ=0），cos θ=1，点积达到最大；垂直时 cos θ=0，点积为 0。 所以点积本质上是在问：这两个向量的方向有多一致？

注意它同时受“长度”影响：一个很长的向量即使方向偏一点，点积也可能很大。 在注意力里这不是问题——因为 Q、K 都是同一套线性变换产出的，尺度大体可控； 而且后面还会除以 √dk 做校正（见第 08 页）。

4矩阵：一批向量打包在一起

先看最小的一个动作：C 的一个格子是怎么算出来的。

矩阵matrix§3.2.1 Q、K、V

是什么：按行、列排成矩形的数表。形状记作“行数 × 列数”，例如 2×3 表示 2 行 3 列。

为什么需要：GPU 一次算一个数太浪费。把 n 个词的向量堆成一个 n×d 的矩阵， 一次矩阵乘法就能同时处理所有词——这正是 Transformer 能并行的物理基础。

论文里的样子：一句话 10 个词、每词 512 维，输入就是 10×512 的矩阵 X。 Q = XWQ 一次就得到全部 10 个词的 Q，而不是循环 10 次。

易错：矩阵的“第 i 行”通常对应“第 i 个词”，这是本课的约定，也是论文的约定。 读代码时如果发现转置过，行和列的含义会互换，务必先确认形状。
2矩阵乘法的机械流程形状优先
输入
A（n×k）与 B（k×m）
条件
A 的列数必须等于 B 的行数（都是 k）。不满足就不能乘，这是唯一的合法性检查。
步骤 1
先算结果的形状：(n×k)·(k×m) → n×m。中间那个 k 被“消掉”。
步骤 2
结果第 i 行第 j 列 = A 的第 i 行 与 B 的第 j 列 做点积。
步骤 3
对每个 (i, j) 重复，共 n×m 次点积。每次点积做 k 次乘加。
结果
一个 n×m 的新矩阵。
易错
① 忘了检查中间维度是否相等；② 把“行乘列”写成“行乘行”； ③ 以为 AB = BA（矩阵乘法不满足交换律，交换后甚至形状都不合法）； ④ 在注意力里把 QKT 写成 KQT——形状会变成 m×n，行列含义完全反了。

5转置：为什么偏偏是 QKT

转置transpose§3.2.1 式(1)

是什么：把矩阵的行和列对调，记作上标 T。原来的第 i 行变成第 i 列。 形状从 n×k 变成 k×n。

为什么需要：Q 是 n×dk，K 也是 n×dk。两个都是“行=词、列=特征”， 直接乘不合法（列数 dk ≠ 行数 n）。把 K 转置成 dk×n 之后， Q(n×dk) · KT(dk×n) = n×n，中间维度对上了。

结果的形状说明了什么：n×n 的矩阵，第 i 行第 j 列 = 第 i 个词的 Query 与第 j 个词的 Key 的点积。 也就是“第 i 个词给第 j 个词打的分”。每一行是一个词的完整注意力分布。

易错：QKT 的第 i 行第 j 列，是“i 看 j”，不是“j 看 i”。 方向搞反会导致后面所有解释都错位。

把公式读成一句话：QKT 得到“词 × 词”的分数表 → 除以 √dk 压小数值 → softmax 把每行变成总和为 1 的百分比 → 乘 V 按百分比取信息。四个动作，四个形状，缺一不可。

6线性变换：矩阵就是“可学习的加工方式”

线性变换 / 线性层linear transformation§3.2.2；§3.3

是什么：y = xW + b。x 是输入向量，W 是一个矩阵（权重），b 是偏置向量。 整件事就是一次矩阵乘法加一次加法。

为什么需要：它能把 512 维的“通用词向量”转换成特定用途的表示。 注意力里用三个不同的 W，就把同一个词向量变出 Q、K、V 三种角色。

W 从哪来：不是人设计的，是训练出来的。初始随机，通过梯度下降一点点调整（见第 02 页）。 论文中 WQ 形状是 512×64（多头的每一头）。

易错：线性变换不会改变“词与词之间的关系结构”以外的东西——它不做非线性弯折。 这也是为什么必须有 ReLU（第 11 页）：只堆线性层，等于一层。

本页要点

  1. 向量是一串数；维度 = 分量个数；一个词 = 一个 512 维向量。
  2. 点积 = 对应位置相乘再求和，得到一个数，衡量两个向量的方向一致性。
  3. 矩阵乘法 = “左行 · 右列”逐格点积；形状规则 (n×k)(k×m)=(n×m)，中间维度必须相同。
  4. 转置把行变列。QKT 的形状是 n×n，第 i 行 = 第 i 个词的注意力分布。
  5. 线性层 = 矩阵乘法 + 偏置，矩阵参数由训练得到。

7自测

Q1向量 a=[1,2,0] 与 b=[3,0,4] 的点积是多少？
逐对相乘：3、0、0，相加得 3。第二项 2×0 和第三项 0×4 都贡献 0，但位置不能错。
Q2若 Q 的形状是 10×64，K 的形状也是 10×64，那么 QKT 的形状是？
K 转置后是 64×10，(10×64)·(64×10) = 10×10。这个 10×10 就是“10 个词互相打分”的分数表，每行一个词的注意力分布。
Q3下面哪句话是错的？
相乘的条件是“左列数 = 右行数”，与元素总数无关。2×6 和 6×2 能乘，2×6 和 2×6 不能乘。
