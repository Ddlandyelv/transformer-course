1先把 §3.2 那句定义读薄

原文的定义只有一句，但塞了四个名词：

“An attention function can be described as mapping a query and a set of key-value pairs to an output, where the query, keys, values, and output are all vectors. The output is computed as a weighted sum of the values, where the weight assigned to each value is computed by a compatibility function of the query with the corresponding key.”

翻译成大白话：

  1. 你有一个问题（query）。
  2. 面前有一堆条目，每条有一个标签（key）和一份内容（value）。
  3. 你拿问题跟每个标签比对，算出一个匹配度（compatibility）。
  4. 按匹配度把内容加权混合，得到你要的答案（output）。

就这么简单。剩下的所有复杂度，都来自“怎么算匹配度”和“怎么把权重归一化”这两个工程选择。

注意力attention§3.2

是什么：一种“按相关程度加权汇总”的操作。它不是查找（只取一个），而是软查找： 所有条目都取一点，相关的取多一点。

为什么用“软”的：硬选择不可导，没法用梯度训练。加权平均是可导的，可以端到端学习。

易错：注意力不是“关注最重要的那个”。它是按比例混合全部，即使最不相关的也有一点点权重（除非被掩码）。

2Q、K、V：一个词的三套身份证

同一个词向量 x（512 维），乘三个不同的矩阵，得到三套表示：

q = xWQ    k = xWK    v = xWV WQ、WK、WV 形状都是 512×64（单头情况下 dk=dv=dmodel）
Query 查询Q§3.2

是什么：当前这个词“想找什么”的表示。

类比：你在图书馆检索框里输入的关键词。

易错：Q 不是“词本身”，而是“这个词在提问时的样子”。同一个词在不同层、不同头里，Q 的用途都不同。
Key 键K§3.2

是什么：每个词“我是什么”的表示，用于被匹配。

类比：书脊上的分类标签。你不是拿走标签，只是拿它做比对。

易错：K 和 V 是分开的两套向量。很多人以为“匹配上就把这个词本身搬过来”——不是，搬过来的是 V。
Value 值V§3.2

是什么：每个词“我能提供什么内容”的表示。权重算好之后，真正被加权求和的是它。

类比：书的正文。标签决定借哪本，正文才是你带走的东西。

易错：如果 K 和 V 用同一个矩阵（K=V），模型就失去了“按一种标准匹配、按另一种标准取内容”的灵活性。论文特意分开。

为什么非要拆成三个？因为“匹配的标准”和“取走的内容”常常不是一回事。 比如代词“它”要找的是“前面出现过的、单数的、非人的名词”——这是匹配标准； 而它真正需要吸收的信息可能是“动物”的语义特征——这是内容。 用同一套向量同时承担两个职责，会互相牵制。

3公式的四个动作

Attention(Q, K, V) = softmax( QKT / √dk ) V 式 (1)。括号里的结果叫“注意力权重”，再乘 V 得到输出
①打分：QKTn×dk · dk×n → n×n
做什么
每个 Query 与每个 Key 做点积，得到一张“词 × 词”的相似度表。
条件
Q 与 K 的列数必须相同（都是 dk）。这也是多头里每头都用 64 维的原因。
结果
n×n 矩阵。第 i 行第 j 列 = 第 i 个词给第 j 个词打的分。数值无界，可正可负。
易错
写成 KQT（行列含义反了）；忘记转置导致形状不合法；把 batch 维度漏掉（实际是 b×n×n）。
②缩放：除以 √dk逐元素
做什么
把 n×n 矩阵里的每个数都除以 √dk。
条件
必须在 softmax 之前做。放在之后没有任何意义（那时已经是概率了）。
结果
形状不变，数值范围被压小，softmax 不会饱和。
易错
除以 dk 而不是 √dk（压得过头，注意力变得过于平均）；dk=64 时 √dk=8。
③归一化：softmax按行
做什么
对每一行做 softmax，使每行正数、求和为 1。
条件
如果要用掩码（解码器），必须在 softmax 前把非法位置设成 −∞，否则 softmax 之后没法再置零。
结果
n×n 的权重矩阵，每行是一个概率分布。
易错
对整个矩阵做 softmax（应该按行）；掩码放在 softmax 之后（那样权重和不再是 1）。
④汇总：× Vn×n · n×dv → n×dv
做什么
用权重矩阵的每一行，对 V 的所有行做加权平均。
条件
权重的列数（n）必须等于 V 的行数（n）——两者都来自同一个序列，天然对上。
结果
n×dv。第 i 行 = 第 i 个词“看过全句之后”的新表示。
易错
以为输出是某个词的 V 的复制——它是所有 V 的混合，只是权重不均。

为什么这四步可以并行

注意：整个过程没有任何一步依赖“上一步的结果”。所有词的 Q、K、V 都能同时算， 整个 n×n 分数矩阵一次矩阵乘法就能出。这正是 Transformer 相对 RNN 的根本优势—— 不是算得更少，而是能同时算。

4亲手算一遍

下面用三个词、每个向量 4 维（dk=4，所以 √dk=2）走一遍全过程。 点“下一步”跟着看，每一步的数值都能自己验算。

验算一下第 3 步：「它」这一行的缩放后分数是 [1, 2, 1]。 e¹≈2.718、e²≈7.389、e¹≈2.718，总和 12.826。 于是权重是 2.718/12.826≈21%、7.389/12.826≈58%、2.718/12.826≈21%。 58% 就是从「动物」取走的信息比例。

5为什么要除以 √dk（本页最难的一点）

论文给的理由很简短，用一个脚注补完了证明：

“We suspect that for large values of dk, the dot products grow large in magnitude, pushing the softmax function into regions where it has extremely small gradients. To counteract this effect, we scale the dot products by 1/√dk.”

第一步：点积为什么会变大

假设 q 和 k 的每一维都是独立的随机变量，均值 0、方差 1。那么点积 q·k = Σ qᵢkᵢ 是 dk 个独立项的和，每一项的方差是 1。 方差可加，所以点积的方差 = dk，标准差 = √dk。

dk=64 时，标准差是 8。也就是说分数经常落在 ±16、±24 这种量级上。

第二步：大分数为什么有害

softmax 对输入做指数。分数一大，最大的那个就把其他全部压死。举个具体例子：

输入 logitssoftmax 结果说明
[0, 1, 0][0.21, 0.58, 0.21]分散，梯度良好
[0, 8, 0][0.0003, 0.9994, 0.0003]几乎 one-hot，另外两个词的梯度≈0
[0, 30, 0][≈0, ≈1, ≈0]完全饱和，学不动

一旦 softmax 输出接近 one-hot，它对输入的导数就接近 0。梯度传不回去，注意力就“冻住”了—— 模型不再学习该关注谁。

第三步：除以 √dk 正好把方差拉回 1

除以 √dk 后，点积的方差变成 dk/(√dk)² = 1。分数回到“个位数”量级， softmax 落在梯度良好的区间。

一句话记住：√dk 不是玄学常数，它是“把点积的标准差从 √dk 拉回 1”的那个数。

常见误解：“除以 √dk 是为了让输出数值变小、防止溢出。”不准确。 它防的不是数值溢出，而是 softmax 饱和导致的梯度消失。这两个问题在数值上相关，但机理不同。

6为什么用点积，而不是加性注意力

论文提到两种常见的注意力打分方式：

  • 加性注意力（additive，Bahdanau 2015）：用一个小的前馈网络算 v·tanh(W₁q + W₂k)。
  • 点积注意力（dot-product）：直接 q·k。

理论上两者复杂度相近，但点积能直接用高度优化的矩阵乘法库，更快、更省显存。 代价是：dk 很大时点积数值会失控——这正是缩放因子要解决的问题。

方式打分函数速度大 dk 时
加性小型前馈网络慢（多一层）稳定
点积（不缩放）q·k快数值爆炸、softmax 饱和
点积 + 缩放q·k/√dk快稳定

所以式 (1) 的那个除法，本质上是“用一行代码换回了加性注意力的稳定性，同时保留了矩阵乘法的速度”。

7易错清单（读完自检）

  • ❌ 以为 softmax 对整张矩阵做 → ✅ 按行做，每行和为 1。
  • ❌ 以为缩放放在 softmax 之后 → ✅ 必须之前。
  • ❌ 以为输出是“最相关那个词的 V” → ✅ 是所有 V 的加权混合。
  • ❌ 以为 Q、K、V 是三个不同的输入 → ✅ 同一输入乘三个不同矩阵。
  • ❌ 以为注意力有权重就一定能解释 → ✅ 权重是模型学出来的，未必符合人类直觉。
  • ❌ 以为 dk 是“词向量维度” → ✅ 是每个头的维度（64），不是 512。

本页要点

  1. 注意力 = 用 Q 和 K 算匹配度，再用匹配度对 V 做加权平均。
  2. Q/K/V 是同一输入乘三个矩阵；匹配靠 K，取内容靠 V。
  3. 四个动作的顺序不可换：打分 → 缩放 → （掩码）→ softmax → 乘 V。
  4. 除以 √dk 是因为点积方差 ≈ dk，不缩放会让 softmax 饱和、梯度消失。
  5. 整个过程无数据依赖，可整句并行——这是相对 RNN 的根本优势。

8自测

Q1若 dk = 64，缩放因子 √dk 约等于多少？
√64 = 8。所以点积分数会被除以 8，把标准差从 8 拉回 1。
Q2把缩放放到 softmax 之后，会发生什么？
缩放的目的就是让 softmax 的输入落在舒适区。放到后面，饱和已经发生；而且概率被除以 8 后不再归一。
Q3注意力输出向量的第 i 行，最准确的描述是？
权重不同，所以不是平均；也不是只取一个。它是 soft lookup 的结果。
